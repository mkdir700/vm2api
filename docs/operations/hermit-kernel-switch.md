# 现有槽位的 Hermit 切换与回滚

## 适用范围

本流程适用于本机 Linux Docker Claude 槽位。
管理员可在 cli-node、CRAG v2 与 Hermit 之间切换。
本流程覆盖进入 Hermit、更新 Hermit 版本及从 Hermit 切回原生内核。
原生内核之间的切换继续使用原有入口。
远程槽位、KVM 槽位和 Codex 槽位不能使用本流程。

切换以单个槽位为事务边界。
批量应用会逐个执行，并分别报告结果。
某个槽位失败时，已经切换成功的其他槽位不会自动回滚。

## 激活条件

生产包应同时声明以下条件：

- `acceptance` 为 `production`。
- `capabilities.production` 为 `true`。
- `capabilities.helper_integration` 为 `true`。
- `capabilities.https_upstream` 为 `true`。
- `capabilities.switch_readiness` 为 `true`。
- `target` 为 `linux-amd64`。

服务器还会验证包摘要、固定 Claude Code、客户机环境和 tmux 摘要。
服务器要求槽位具有可用的出口绑定和格式有效的凭据。
服务器按包能力检查系统提示词和工具流式设置。
生产模式固定使用 HTTPS 上游。
生产模式不要求开启实验环境变量。

模拟验收包仍不能激活生产槽位。
Linux 正式构建会声明已验收的生产部署能力。
旧模拟包保持原清单，不会自动升级为生产包。
生产部署能力不代表真实账号验收。

## 准备生产包

1. 在干净的 Hermit 工作树中运行 `deploy/kernel_package.py build`。
2. 指定 `--target linux-amd64` 和一个新的版本号。
3. 指定固定 Claude Code 和固定 tmux 的文件路径。
4. 添加 `--external-cli`，复用按摘要缓存的官方 CLI。
5. 保存版本归档及 `release.json`。

Linux 构建使用已验收的生产部署声明。
Darwin 构建保持模拟声明。
不要修改旧包的清单。上传具有新版本号的生产包。

## 准备协议设置

新包通过能力声明支持现有协议设置。
具有 `system_prompt: true` 的包允许保留 vm2api 的系统提示词处理。
具有 `eager_tool_streaming: true` 的包允许开启“工具参数流式下发”。
这类包不要求管理员打开“官方 Claude Code 家族透传”或关闭工具参数流式。

应用内核不会修改全局设置。
旧包缺少对应能力时，系统仍在停止旧内核前拒绝不支持的组合。
先升级内核包，再应用槽位。
不要为单个 Hermit 槽位修改其他槽位共用的全局设置。

同一请求中的工具流式策略必须统一。
vm2api 的全局开关产生统一策略。
调用方混合指定逐工具的 `true` 和 `false` 时，Hermit 明确拒绝请求。
系统提示词文本通过原版 CLI 的提示词文件入口生效。
缓存标记由原版 CLI 序列化，不作为提示词正文写入。

## 后台操作

警告：先结束所选槽位的工具调用。切换会重启内核并重建本槽容器。
系统会保留凭据、会话文件和机器标识。系统不会迁移旧进程的内存状态。

1. 打开后台的“内核”页面。
2. 安装 Hermit 版本归档及对应的 `release.json`。
3. 选择要切换的 Claude 槽位。
4. 在目标版本处单击“切换并应用”。
5. 确认所选槽位和切换说明。
6. 等待每个槽位返回结果。

管理员也可打开槽位详情的“推理内核”区域。
选择已安装的 Hermit 版本，然后单击“切换并应用”。
两个入口使用相同的后端事务。
“暂存到所选槽位”只保存待选版本，不会切换运行内核。

警告：回滚保留期间，不要手动启动或清理旧容器。

切换完成后，旧容器保持停止。
后台会显示“回滚上次切换”和“确认保留当前内核”。
上次切换未回滚或确认前，系统会拒绝下一次不同内核的切换及重装。
重复应用当前 Hermit 版本只检查当前内核，不会重建容器。

## 自动切换顺序

1. 验证目标包、凭据、出口及协议配置。
2. 写入切换记录。
3. 暂停本槽调度，并暂停本槽的 watchdog 恢复。
4. 等待在途请求结束，最长等待 120 秒。
5. 检查当前内核是否允许切换。
6. 停止旧内核和旧容器。
7. 关闭旧容器的自动重启，并重命名旧容器。
8. 创建目标容器，并启动目标内核。
9. 检查目标内核的健康状态及内核身份。
10. 原子写入目标选择、运行状态和切换完成记录。
11. 恢复本槽原有的调度状态。

原来关闭调度的槽位仍关闭调度。
原来停止的槽位会短暂启动目标内核以验证健康，然后恢复停止状态。
系统不会恢复其他槽位的调度。

Hermit 会报告 `switch_ready` 和 `pending_tool_results`。
系统要求当前交换完成，并且所有工具结果均已返回。
HTTP 响应结束后仍有外部工具等待时，系统会拒绝切换。
旧包未提供切换就绪证据时，系统也会拒绝停止仍在运行的 Hermit 内核。
控制平面重启后，系统会先重新接管当前 Hermit 内核，再检查就绪状态。

## 失败回滚

目标内核未通过健康检查时，系统会自动回滚。
系统先确认旧容器的完整 ID，再移除本次创建的目标容器。
系统恢复旧容器的名称、自动重启策略和内核选择。
原来运行的旧容器通过健康检查后，系统才恢复原有调度状态。

回滚只恢复内核选择及容器。
回滚不会恢复旧凭据快照。
旧内核会读取当前凭据文件。

旧容器缺失、身份不匹配或回滚健康检查失败时，系统会返回 `kernel_rollback_failed`。
系统会保留维护暂停状态。
系统不会将回滚失败报告为成功。
旧容器无法确认时，系统不会先删除当前容器。

## 显式回滚

1. 打开本槽的“推理内核”区域，或在内核页选择本槽。
2. 单击“回滚上次切换”。
3. 确认回滚范围。
4. 等待后台确认旧内核恢复。

回滚前，系统同样会等待在途请求并检查工具结果。
当前内核失联时，可先停止本槽，再重试回滚。

切换记录保存在槽位记录的 `kernel_transition` 字段中。
控制平面重启不会丢失回滚容器 ID、原内核选择或原调度暂停信息。
切换中断后，watchdog 和调度器会跳过未完成的事务。
修复容器或文件权限后，重新执行“回滚上次切换”。

## 确认当前内核

警告：确认会删除本次保留的旧容器。确认后不能通过本记录回滚。

1. 验证当前内核符合使用要求。
2. 单击“确认保留当前内核”。
3. 确认删除旧容器。

确认请求中断后，重新查询切换状态。
状态仍为 `applied` 时，重新执行确认。
状态已为 `finalized` 时，确认已经完成。

系统只删除切换记录中 ID 匹配且保持停止的旧容器。
系统保留凭据、会话文件和已安装的内核包。

## 接口

管理员可查询 `GET /api/panel/vms/:id/kernel-transition`。
响应中的 `transition` 为 `null` 或切换摘要。
摘要不包含宿主目录、容器备份路径或凭据。

管理员可提交 `POST /api/panel/vms/:id/kernel-transition`。

```json
{
  "action": "apply",
  "target": {
    "dataplane": "hermit",
    "target": "linux-amd64",
    "version": "已安装的版本"
  }
}
```

切回 cli-node 时，使用 `{"action":"apply","target":{"dataplane":"wrap"}}`。
切到 CRAG v2 时，使用 `{"action":"apply","target":{"dataplane":"crag"}}`。
CRAG v2 还要求安装包和有效授权。
回滚使用 `{"action":"rollback"}`。
确认使用 `{"action":"finalize"}`。

切换成功返回 HTTP `200`。
切换被拒绝或回滚未完成时，接口返回 HTTP `409` 并提供错误码。
普通用户和超级用户不能调用该接口。

原有 `POST /api/panel/dataplane` 的 Hermit 应用也会委托该事务。
从 Hermit 切回原生内核的槽位详情入口同样使用该事务。
全局切换不能隐式转换 Hermit 槽位。
