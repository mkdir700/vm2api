状态：实现与本地端到端验收完成；尚未发布。

## 术语

| 术语 | 本文含义 |
| --- | --- |
| 调用方范围 | 已认证用户、API key、分组和推理后端的隔离范围 |
| slot | vm2api 选中的运行槽位，以 `vm_id` 标识；实验中也记录其内核 socket 和账号 |
| 原生 owner | slot 内承载原生 CLI 会话的运行实体；同一 slot 可以承载多个 owner |
| 请求身份 | 调用方范围与推理输入的稳定指纹，用于固定 slot |
| 执行身份 | 一次独立生成的身份；内容相同的两次 HTTP 调用也可以有不同执行身份 |
| 提示词缓存 | 上游复用已计算的输入前缀；每次调用仍生成新的输出 |
| 幂等重放 | 返回同一次操作此前的结果；不属于本次重复调用需求 |

本文的“相同 slot”不等于“相同原生 owner”。
原生 owner 是否可替换，必须由实际序列化前缀实验决定。
更换 session 既不能单独证明缓存失效，也不能单独证明缓存命中。

## 决策

### 1. 请求身份与执行身份分离

相同推理输入可以形成多次独立生成。
不得仅因请求体相同而返回 400。
不得复用第一次答案冒充模型生成或上游缓存命中。
已有执行内部的重复投递保护仍然有效。
未完成执行与工具等待必须保留原有绑定和结果校验。

请求指纹包含模型、system、messages、tools、工具选择、思考、采样、输出约束及缓存控制等推理相关内容。
JSON 对象键排序和无意义空白不影响指纹。
数组顺序和字符串内容不能改变。
请求 ID、追踪 ID和流式交付方式不参与推理输入指纹。
指纹必须包含调用方隔离范围，禁止跨租户复用绑定。
只保存不可逆指纹，不在调度绑定中保存提示词正文。

### 2. 相同请求固定到同一个 slot

首次请求通过现有调度选择可用 slot，并以原子操作保存绑定。
后续相同请求只能回到该 slot。
账号粘性不能替代 slot 绑定。
保持账号、凭据代际和缓存相关身份稳定；变化必须显式记录。

- slot 忙：在该 slot 排队，受明确截止时间限制。
- 超时或过载：返回明确错误，不跨 slot 重试。
- slot 不可用、删除或失去权限：返回明确错误，不自动重分配。
- 并发首次请求：只能产生一个胜出的绑定。
- 重启：绑定必须恢复，不能因进程重启而换 slot。

缓存过期不构成自动重新分配 slot 的理由。
绑定失效后的重新分配需要单独定义显式操作，本阶段不新增配置层。

### 3. 缓存身份不跟随每次执行变化

重复生成必须保持工具、系统提示词和缓存断点前的消息内容稳定。
不得向可缓存前缀注入每次变化的 session ID、时间或随机标记。
缓存相关的上游路由身份应保持稳定。
仅更换传输请求 ID 不应使新请求变成旧执行的重复投递。

优先验证在原 slot 内创建独立执行或从发送前状态建立新 owner。
若现有 CLI 在新 owner 中改变了前缀，则该路径不能作为已验证方案。
不得删除调用方内容、签名、工具结果或修改 system 来绕过重复检查。

### 4. 证据分层

1. HTTP 模拟实验验证固定 slot、等待、超时、不可用与租户隔离。
2. 真实 Hermit 与固定 CLI、模拟上游实验验证重复冲突和实际序列化前缀。
3. 真实上游实验验证实际缓存读取用量与新输出生成。

前两层不能证明第三层成功。
模拟上游不得伪造缓存计数后宣称真实缓存命中。
真实上游调用遵守 Hermit 的单独授权要求。

## 实验前失败清单

- 将相同输入误判为同一次执行，第二次返回 `completed_request_duplicate`。
- 新建 owner 导致 tools、system 或 messages 前缀变化。
- 缓存读数来自模拟响应或本地推算。
- slot 忙或不可用后偷偷切换其他 slot。
- 并发首请求产生两个绑定，重启后遗失绑定。
- 不同调用方的相同提示词共享了 slot 绑定。
- 通过返回旧答案绕过真实生成。
- 重放已执行工具、释放同一工具结果两次或破坏签名拒绝策略。
- 停止 owner 时误终止生产进程，或实验结束后遗留子进程。

## 当前结论

原 slot 内创建独立原生会话的方向通过本次实验。
新原生会话不是提示词缓存的强制失效条件。
生产实现应分开保存固定 slot 的请求身份与每次生成的执行身份。
正常对话续接继续复用兼容 owner；已完成输入的再次生成使用独立执行。
不得通过修改前缀来制造执行身份。

## 实现与最终验收

### 实现范围

普通原生 Claude 请求现在直接使用生产 HTTP 路径完成固定 slot 绑定，不再依赖实验代理。
范围包含 Anthropic Messages 及转为 Claude 的 OpenAI 兼容请求。
独立 API 后端、Codex 后端、分类器和管理员明确指定 slot 的诊断请求保留各自原有路径。

新增迁移 `056_request_slot_bindings.sql`，使用两个 SQLite 表：

- `request_slot_bindings` 保存请求指纹对应的 slot、账号和稳定缓存身份。绑定不自动过期，不随 slot 删除而移除。
- `request_slot_executions` 按请求指纹及调用会话保存执行身份和状态。状态区分执行中、等待工具、已完成和不确定。

请求指纹在原始输入上计算，不包含流式交付、metadata、会话和追踪标记。
指纹包含 API key、用户、分组、协议及推理输入。
请求指纹和调用会话使用现有队列串行化。
首次 slot 认领使用 SQLite 原子插入；冲突时释放未使用的预留并服从已保存的绑定。

调度器将固定 slot 作为候选过滤条件，保留健康、账号状态、额度、所有权及 API key 范围检查。
这不同于管理员诊断 pin，不会跳过停用和额度约束。
上游失败后立即返回本次错误，不切换 slot。
已绑定 slot 不可用时返回 503 `bound_slot_unavailable`。
绑定或执行状态存储不可用时返回 503 `request_slot_store_unavailable`。
队列超时继续使用明确的过载响应。

已完成请求再次生成时使用新执行会话。
等待工具结果或执行结果不确定时保留原执行身份，不自动重放。
同一 API key 下的不同外部会话保持各自独立的工具等待状态。
一次工具续接完成后，系统将同一原生会话中此前等待工具的输入标记为已完成。

稳定缓存身份与新执行身份分开。
网关自有计费前缀中的 prompt ID 使用稳定缓存身份，避免随机执行 ID 改变缓存前缀。
同一认证范围及外部会话的正常续接，继承此前的缓存身份。
调用方的提示词和签名不作为修复对象。

### 最终真实上游验收

路径为真实 vm2api HTTP → API kernel → 隔离 Hermit slot → 固定 CLI → 现有 `kin-02` 中的只读认证转发 → 正规 Claude 上游。
4 次调用使用同一个外部会话及相同请求体，未使用实验路由代理。
实际调度只选择一个 vm_id，产生 4 个独立的执行会话和原生 owner。

| 调用 | HTTP 状态 | 缓存写入 token | 缓存读取 token | 输出 token |
| --- | --- | --- | --- | --- |
| 1 | 200 | 15,395 | 0 | 5 |
| 2 | 200 | 0 | 15,395 | 5 |
| 3 | 200 | 0 | 15,395 | 5 |
| 4 | 200 | 0 | 15,395 | 5 |

每次调用都有独立的上游 request ID。
实际序列化的 tools、system 和 messages 前缀保持一致。
本次新增 4 次调用，连同前序实验共使用 9/9 次授权，未增加直接对照或继续消耗额度。
真实验收后补充了正常续接的缓存身份继承，以及已确认工具续接完成后对不确定历史状态的收束。
这两项补充已由最终 HTTP 与隔离原生链路验证，未再次调用真实上游。
收据分别保存真实验收候选源码与最终源码哈希，不将两者混为同一源码快照。

### 本地回归

- 5 个生产 HTTP 端到端用例覆盖重复与并发生成、规范化、流式交付、重启、API key 隔离与权限收窄、停用、等待超时、取消、上游失败、工具生命周期和存储故障。

- 真实原生链路的 14 项检查通过。工具等待时的重复提交被拒绝；已完成工具历史重新生成时没有新工具调用；实际外部效果收据只有一条；工具续接完成后可以重新生成最初输入。
- 临时网关、API kernel、Hermit 及 owner 进程组均已清理。

尚未进行 Linux 发布镜像验收、真实 OpenAI 上游验收、完整生产入口部署验收或多进程共用数据库验收。
每个控制器仍采用现有单进程 SQLite 模式；上线时必须保留同一数据库和 slot 身份。
部署组切换不得丢弃或绕过这些绑定；跨部署组生命周期不属于本次验收。
