## 升级过程与恢复修复

首次任务 `9fcc4d3359e042eaa4d5945e85edbdb3` 在原健康内核检查阶段失败。
旧控制镜像恢复后，Hermit 的 stdin 所有者没有自动重建。
系统保留调度暂停，要求恢复。

通过原版本的同版本切换入口重新建立所有者后，旧内核恢复健康。
随后核对原镜像、凭据、槽位记录和内核健康，再恢复原任务的调度状态。
首次任务最终记录为 `ROLLED_BACK`。原错误和人工恢复事件保持可查。

修复提交 `f6de76af` 在打开 HTTP 服务前恢复运行中 Hermit 槽位的进程租约。
该提交还补齐由 `homeDir` 推导的项目路径。
修复的端到端测试先在旧镜像复现，再验证连续两次控制平面启动。
详见[重启恢复记录](hermit-controller-restart-20261109.md)。

重新构建和复验正式镜像后，第二次统一离线升级成功。
随后通过 `kernel-transition apply` 更新现有 Hermit 槽位。
上线核对通过后执行 `finalize`，再执行一次上线核对。
