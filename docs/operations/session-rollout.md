# 会话部署组与 tag 发布契约

状态：代码已实现，处于隔离验收阶段。生产未启用。目标为单宿主机 Compose。生产入口沿用已核实的 OpenResty。

## 状态与所有权

网关复用现有 ApiKeyStore 的身份与额度算法，持久化会话归属、准入、RPM 和结算去重。sub2api 保留其客户账本。网关的 vm2api API Key 账本是内部调用额度，不能在两个业务组分别累计。业务组只读权威身份库，组内执行与诊断数据独立。

每个业务组独立持有数据、槽位、账号刷新、socket、Hermit stdin 租约。共享目录仅允许只读的权威身份库和不可变包。活动账号不得复制到两组。没有稳定会话标识时按 API Key 保守固定归属。父子 agent 共享部署组，组内执行身份保持现有规则。

网关按 `request_id` 预留准入，先持久化再发送。发送后遇到断线、取消或崩溃不能释放未知占用。业务组保存执行回执，网关按请求 ID 幂等结算。回执重传不重新执行。保留非终态占用直到核对成功。内部请求签名绑定组、请求、方法、路径和有效期；业务组拒绝无签名与重复执行。

归属不能靠 TTL 删除。工具等待、恢复和未知状态阻止停止。显式关闭会话必须在网关无未决请求且后端排空证明通过后进行；调用者不能伪造关闭证明。无稳定身份的归属只允许运维明确核对后关闭。

## 发布事务

候选注册 → 业务就绪 → 修改新会话策略 → 旧组仅续接 → 汇总排空 → 停止旧组。策略使用预期代次，防止旧任务覆盖新任务。所有生产任务共用宿主机文件锁。CI 不直接执行任意发布清单中的 shell。工件摘要、服务器受保护部署配置与固定执行器决定可执行动作。

排空证明绑定组和实例。必须包含网关未决准入、未关闭归属以及后端活动请求、队列、工具等待、helper 和恢复状态。失联、字段缺失和过期均拒绝停止。正常发布不使用 SIGTERM 的强制超时完成排空。

数据库仅进行新旧兼容变更。破坏性迁移拒绝自动蓝绿。回滚只改变后续新会话的归属。已有归属继续使用原组。

## 实施前失败场景

1. 同一会话同时首次访问，创建两个归属；不同 API Key 的相同会话串组；父子 agent 跨组。
2. 伪造内部签名、目标组、过期签名或请求 ID 重放；提示词、密钥出现在回执。
3. 流式输出在切流时中断；工具结果错误进入新组；没有身份的客户端被随意迁移。
4. 网关或发布器在预留、发送、结算、切流后崩溃；未知请求自动重放；重复用量结算。
5. 两组重复计算总并发、RPM 或用量；网关重启清空占用。
6. 旧组仍有工具等待、helper、恢复或未结算却被停机；失联被当作零；排空报告来自另一实例。
7. 候选失败仍切流；并行 tag 互相覆盖；旧任务覆盖新策略；发布器中断后重复创建容器。
8. 新旧组共享可变目录、账号或端口；迁移破坏旧版；回滚覆盖生产数据。
9. 测试结束遗留网关、控制面或内核进程；工件不能对应源码。
10. sub2api 的 HTTP 请求已完成，但异步计费队列仍未结束。请求计数与计费队列必须同时为空。

## 端到端验收

先实现真实网关进程、两个受控 HTTP 后端和持久数据库的完整验收，再使用真实 vm2api HTTP 网关与 Hermit 原生槽位夹具验证适配。受控运行时不代表真实账号、上游或生产部署已验收。每轮保存 summary、源码摘要、请求回执、发布事务和清理结果。禁止以健康检查代替完整执行链路。
